# 08 达芬奇装配、输出与检查

本章讲成片流水线的最后一段：剪辑脚本 work/v16k/edit18.py 已经把全片（每个镜头、每处转场、全部文字）定义好以后，怎样把它变成交付的三个文件。

1. 用 work/v16k/export18.py 把全片拆成一组 ProRes（苹果的专业中间编码格式，画质高，适合剪辑和合成）素材，并写一份时间线计划 plan.json；
2. 在 DaVinci Resolve Studio 21.1 的脚本环境里运行 work/v16k/build_resolve.py，按 plan.json 自动搭出时间线；
3. 由 Resolve 渲染 1080p H.264 成片；
4. 用 ffmpeg 生成 8D 双耳版和手机预览版；
5. 用跳变扫描、接缝联络表、PSNR（峰值信噪比，衡量两帧画面的差别，两帧完全相同时为无穷大 inf）逐帧比对和响度测量做检查。

全部步骤由 AI 编程助手 Claude Code 在作者的 MacBook Pro（Apple M3 Max，128 GB）上执行：它编写并在终端里运行导出和检查脚本，通过 DaVinci Resolve 的脚本接口运行装配与渲染。下文的相对路径都相对于工程根目录 ~/Movies/ZAFU2，命令也都在这个目录下运行。

## 8.2 导出素材：export18.py

### 8.2.1 全片从哪里来

export18.py 用 importlib 加载 work/v16k/edit18.py，调用 edit18.film()，得到六项：

- t0 = 0、t1 = 110.0：全片起止（edit18.END）；
- S：镜头表，每项是（起点秒，终点秒，取帧函数）。取帧函数 fn(t) 返回全片时间 t 处这个镜头的画面：1920x1080、RGB、0 到 1 的浮点数组；
- labels（本片为空）和 texts：全部文字对象；
- trans：接缝字典，键 j 是接缝前那个镜头在 S 里的序号，值是（类型，时长[，参数]）。

脚本里的固定参数（export18.py 第 15 到 18 行）：

| 参数 | 值 | 含义 |
|---|---|---|
| W, H, FPS | 1920, 1080, 25 | 代码镜头、转场和文字层的尺寸与帧率 |
| HANDLE | 0.6 秒 | 每个镜头文件前后多导的手柄（handle：镜头前后多留的画面，供叠化和转场使用） |
| OUTD | renders/v18/elements | 输出目录 |
| SIGNATURE | ink、whip、zoom、pigment、particles3d、mist、reprint、leafwipe、light、lumakey | 这些类型的转场预先渲染成完整画面；其余类型（luma）交给 Resolve 做交叉叠化 |

### 8.2.2 把长镜头拆成片段

edit18 里有两个长镜头（Chain18 对象），在 Python 里各算一个镜头：

- 年代长镜头 16.6 到 24.0 秒：S1、S2、S3、S4 四段 AI 视频首尾相接，前一段的尾帧就是后一段的首帧，所以段与段之间直接相接，画面连续；
- 东湖长镜头 27.4 到 37.8 秒：E2、S7 两段，31.4 秒处用"重印"转场衔接。

export18 把长镜头里的每段 AI 视频拆成独立片段（在达芬奇里各是一个 clip），长镜头内部的特殊转场单独导出一个文件。同一个长镜头里时间上互相重叠的转场窗口会合并成一个连续文件（类型记为 merged，本片没有出现）。拆完后全片共 27 个片段：11 个代码镜头、16 个 AI 镜头，plan.json 里记 "flat": true。

### 8.2.3 命令

导出分几种模式，可以分开跑，也可以用 all 一次跑完。每次运行结束都会重写 plan.json。

导出全部代码镜头：

```bash
.venv_ai/bin/python work/v16k/export18.py shots
```

导出全部 AI 镜头：

```bash
.venv_ai/bin/python work/v16k/export18.py ai
```

导出全部转场（包括长镜头内部的转场）：

```bash
.venv_ai/bin/python work/v16k/export18.py trans
```

导出文字层：

```bash
.venv_ai/bin/python work/v16k/export18.py overlay
```

只导出其中几个片段时加 only=编号，编号是 plan.json 里镜头的 i 或转场的 j，多个编号用逗号分开。例如只导出片尾镜头（i = 26）：

```bash
.venv_ai/bin/python work/v16k/export18.py shots only=26
```

只导出进入片尾的水墨转场（j = 21）：

```bash
.venv_ai/bin/python work/v16k/export18.py trans only=21
```

另外两种模式：chainx 只导出长镜头内部的转场；plan 不编码任何文件，只重写 plan.json。注意：trans 模式不管有没有 only=，都会把长镜头内部的转场（X0314_reprint.mov）一起导出。

文字层 2750 帧在本机导出约 3 分钟。

### 8.2.4 编码格式、命名与手柄

编码。export18 把每帧画面写成原始像素流，经管道交给 ffmpeg（函数 enc() 和 put()，第 21 到 28 行）：

| 素材 | 管道输入 | ffmpeg 编码参数 | 得到的文件 |
|---|---|---|---|
| 代码镜头、转场 | rawvideo，rgb48le，1920x1080，25 fps | -c:v prores_ks -profile:v 3 -pix_fmt yuv422p10le | ProRes 422 HQ（apch），10 bit 4:2:2 |
| AI 镜头 | rawvideo，bgr24，原生 1280x720，25 fps | -c:v prores_ks -profile:v 3 -pix_fmt yuv422p10le | ProRes 422 HQ，1280x720 |
| 文字层 | rawvideo，rgba64le，1920x1080，25 fps | -c:v prores_ks -profile:v 4 -pix_fmt yuva444p10le | ProRes 4444（ap4h），带 alpha 通道（透明度通道；ffprobe 读作 yuva444p12le） |

浮点画面写入前先裁到 0 到 1，再乘 65535、加 0.5 取整成 16 位小端整数。

命名：

| 类型 | 文件名规则 | 例子 |
|---|---|---|
| 代码镜头 | shots/S{i:02d}_{tag}.mov；i 是拆开后的片段序号，tag 是取帧函数所属的类名 | S00_Planet18.mov、S26_Title19.mov |
| AI 镜头 | ai/A{i:02d}_{素材名}.mov | A01_AI-1.mov、A25_AI-10.mov |
| 接缝处的转场 | trans/T{j:02d}_{类型}.mov；j 是 edit18 镜头表里接缝前那个镜头的序号 | T03_particles3d.mov |
| 长镜头内部的转场 | trans/X{round(接缝秒×10):04d}_{类型}.mov | X0314_reprint.mov（31.4 秒） |

"一山""一水"两个静帧推移镜头在 edit18 里用 lambda 包了一层，取不到类名，tag 记成 NoneType（S15_NoneType.mov、S16_NoneType.mov），不影响装配。

手柄。每个镜头文件覆盖全片时间 [max(0, a − 0.6), min(110, b + 0.6)]，a、b 是镜头在成片里的起止秒，即前后各多导 0.6 秒（15 帧）；第一个镜头没有前手柄，最后一个镜头没有后手柄。edit18 的取帧函数在镜头时段之外仍给出继续运动的画面（AI 镜头按首尾的速度继续走，素材用完时按首末 5 帧的运镜继续推），所以手柄里不是定格，叠化时两侧都在动。

### 8.2.6 AI 镜头：按成片时间重新生成

AI 原片是 LibTV（Seedance 2.5）生成的 1280x720、24 fps H.264（libtv_jobs/out/<素材名>.mp4）。export18 不让达芬奇去变速，而是按 edit18 定好的时间曲线，逐帧重新生成一份与时间线一一对应的 25 fps 副本（第 77 到 112 行）：

1. 输出第 k 帧对应全片时间 t = file_start + k/25；
2. 源时间 st = src_time(t)：按运动量算出的变速曲线或手工给的节点曲线（edit18 的 AIShotMap，详见[第 5 章](05_剪辑与镜头处理.md)）；超出镜头时段时按首尾速度外推；
3. 画面 = pic(t)：先把每个源帧放回它真实位移对应的时间（AI 视频按 4 帧一组出帧，推进一顿一顿，所以先测真实位移再重排帧时间），再用 DIS 光流生成真正的中间帧（光流：逐像素估计相邻两帧之间的运动；DIS 是 OpenCV 里的 Dense Inverse Search 稠密光流算法）；播放速度超过 2.5 倍时做半帧快门的多帧平均；每帧的细节强度稳定到相邻源帧的中位水平；超出素材两端时，用首末 5 帧拟合出的相似变换（缩放、旋转、平移）继续推；
4. 下表几个镜头额外做颜色处理；
5. 需要放大的段落按 zoom 居中裁切，再用 Lanczos 插值放回 1280x720：S2 固定 1.06 倍；S1 在全片 18.1 到 18.8 秒从 1.0 倍缓动到 1.06 倍，正好接上 S2 的取景；
6. 以原生 1280x720 写出 ProRes 422 HQ。这里不放大，放大交给达芬奇的 Super Scale（见 8.3）。

### 8.2.7 转场

预渲染转场的文件覆盖以接缝为中心的窗口 [at − d/2, at + d/2]，at 是接缝时间，d 是时长（edit18 支持 align='end' 让转场整段落在接缝之前，本片没有用）。第 k 帧时间 t = at − d/2 + k/25，共 round(d × 25) 帧（第 123 到 147 行）：

- A = 前一个镜头的 fn(t)，B = 后一个镜头的 fn(t)，两侧用同一时刻，所以转场过程中两侧画面都在动；
- 画面 = C.TRANS[类型](A, B, u, **参数)，u = (t − 窗口起点) / d，从 0 走到 1。各转场函数的算法见[第 5 章](05_剪辑与镜头处理.md)；
- particles3d（粒子汇聚）调用 work/v16k/particles3d.py 的 render(A0, B1, n, A_seq, B_seq, **参数)：A0 是窗口起点的前镜头画面，B1 是窗口终点的后镜头画面，A_seq、B_seq 是窗口内两侧的逐帧画面，颗粒下面的两侧画面也继续运动；
- 长镜头内部的转场（31.4 秒）直接取长镜头对象的 frame(t)，它在窗口内同样调用 C.TRANS['reprint'](E2 画面, S7 画面, u)。

### 8.2.8 文字层 overlay_text.mov

内容是 edit18.film() 返回的全部文字对象：23 条字幕（每条按标点切成短语，短语在配音开口前 0.08 秒整段浮现，位于画面底部 y = 962、40 像素字号）、"博览古今""学参天地"两列竖排字、片尾 107.4 秒出现的一行"本片部分画面由人工智能辅助生成"等。片尾的校名、年份和"10.25"画在片尾代码镜头 S26_Title19 里，不在文字层。字幕的切分与对时见[第 1 章](01_文案配音与时间表.md)。

算法（第 148 到 160 行）：

1. 每帧把所有文字对象分别画在全黑底 k0 和全白底 k1 上；
2. 对一个直通（非预乘）颜色为 c、透明度为 α 的像素，k0 = α·c，k1 = α·c + (1 − α)；
3. 所以 α = 1 − mean(k1 − k0)（三个通道取平均），c = k0 / α；α ≤ 0.0001 的像素颜色记 0；
4. 把 (c, α) 写成 16 位 RGBA，编码 ProRes 4444。

得到的是直通 alpha（straight），文字的软边、淡入淡出和半透明都原样保留。文件从 0 秒到 110 秒共 2750 帧，与时间线等长，直接铺满 V4。

### 8.2.9 宣纸纹理 paper_4k.png

宣纸纹理不由 export18 生成，是一张一次性做好的静帧，分两步：

1. 底图 data/v14/paper.png：2048x1152，numpy 程序生成，随机种子 3。由三部分组成：5 层分形噪声做的低频斑驳（最大尺度 256 像素，亮度起伏 ±6%）、σ = 0.7 的细颗粒（±3.5%）、2600 根长 20 到 120 像素的随机纤维（压暗 5%），乘在暖宣纸底色 (0.925, 0.893, 0.828) 上。这张底图也被代码镜头用作纸面。
2. 4K 纹理层：放大到 3840x2160，除以它自己 σ = 60 像素的高斯模糊（只留纤维细节，整体变平），再乘 0.985。

两步都没有单独的脚本文件。第 1 步的完整代码（numpy、scipy、Pillow）：

```python
# a warm rice-paper texture (2048x1152): low-frequency mottling, fine grain, long fibres
import numpy as np
from PIL import Image
from scipy.ndimage import gaussian_filter, zoom
rng = np.random.default_rng(3)
W, H = 2048, 1152
def fbm(scale, oct=5):
    out = np.zeros((H, W)); a = 1.0; tot = 0
    for o in range(oct):
        s = max(2, int(scale / 2 ** o))
        n = rng.random((H // s + 2, W // s + 2))
        n = zoom(n, s, order=3)[:H, :W]
        out += a * n; tot += a; a *= 0.5
    return out / tot
mott = fbm(256) - 0.5
grain = gaussian_filter(rng.random((H, W)) - 0.5, 0.7)
fib = np.zeros((H, W))
for k in range(2600):
    x, y = rng.random() * W, rng.random() * H; ang = rng.normal(0.3, 0.9); L = rng.integers(20, 120)
    t = np.arange(L); xs = (x + np.cos(ang) * t + np.cumsum(rng.normal(0, 0.3, L))).astype(int) % W; ys = (y + np.sin(ang) * t + np.cumsum(rng.normal(0, 0.3, L))).astype(int) % H
    fib[ys, xs] += rng.random() * 0.8
fib = gaussian_filter(fib, 0.6)
base = np.array([0.925, 0.893, 0.828])          # warm 宣纸
v = 1 + mott * 0.06 + grain * 0.035 - fib * 0.05
img = np.clip(base[None, None, :] * v[..., None], 0, 1)
Image.fromarray((img * 255).astype(np.uint8)).save('data/v14/paper.png')
```

第 2 步的代码（用 .venv_ai/bin/python 运行）：

```python
import numpy as np, cv2
from PIL import Image
p = np.asarray(Image.open('data/v14/paper.png').convert('RGB'), np.float32) / 255
p = cv2.resize(p, (3840, 2160), interpolation=cv2.INTER_CUBIC)
lo = cv2.GaussianBlur(p, (0, 0), 60)            # 低频部分
fib = p / np.maximum(lo, 1e-3)                  # 只留纤维细节，整体平坦
out = np.clip(0.985 * fib, 0, 1)
Image.fromarray((out * 255 + 0.5).astype(np.uint8)).save('renders/v18/elements/paper_4k.png')
```

结果：3840x2160，8 位 RGB，平均值 251/255（约 0.985），最暗 233，标准差约 1.5 个色阶。以正片叠底、35% 不透明度叠上去时，画面整体只暗约 0.5%，留下极淡的纸纤维。

### 8.3.2 脚本做了什么

1. 取工程和媒体池（第 22 到 26 行）：resolve.GetProjectManager().GetCurrentProject()，断言工程名为 ZAFU_68_v16。
2. 建媒体池文件夹（第 48 行）：代码片段、AI镜头、转场、字幕、声音、纸纹，各加后缀 BIN_SUFFIX（成片为"代码片段_v5_1"等六个）。已存在则复用。
3. 清场（第 49 到 55 行）：删除同名的已有时间线；清空前五个文件夹里的片段（磁盘上的文件可能已重导，必须重新导入）。纸纹文件夹不清。
4. 导入（第 35 到 70 行）：函数 imp() 按文件路径去重，只导入文件夹里还没有的文件。依次导入代码镜头、AI 镜头、转场文件和 three.js 叠加层、文字层、四条声音分轨、宣纸纹理。
5. 片段属性（第 59 到 64 行）：
   - 所有代码镜头和 AI 镜头设 Super Scale = 2：AI 镜头 1280x720 经 2 倍超级缩放到 2560x1440，再适配到 3840x2160 的时间线；代码镜头 1920x1080 经 2 倍到 3840x2160；
   - three.js 落叶叠加层 FX_T1b_leaves.mov 设 Alpha mode = Straight（它是直通 alpha 的 ProRes 4444）。
6. 建时间线（第 72 到 87 行）：CreateEmptyTimeline(TL_NAME)，再加 4 条视频轨、3 条立体声音轨，命名：

   | 轨道 | 名称 |
   |---|---|
   | V1 | 画面 |
   | V2 | 特殊转场 |
   | V3 | 特殊转场2 |
   | V4 | 字幕 |
   | V5 | 纸纹 |
   | A1 | 旁白 |
   | A2 | 配乐 |
   | A3 | 音效 |
   | A4 | 环境 |

7. V1 画面（第 88 到 100 行）：T0 = 时间线起始帧（90000，即时间码 01:00:00:00），fr(t) = round(t × 25)。对 plan.json 的每个镜头调用 AppendToTimeline：
   - startFrame = fr(a − file_start)：跳过前手柄，除第一个镜头外都是 15；
   - endFrame = startFrame + fr(b) − fr(a)：不含此帧；
   - recordFrame = T0 + fr(a)，trackIndex = 1，mediaType = 1（只放画面）。

   27 个片段首尾相接、没有空隙，手柄留在片段两端供叠化使用。
8. 交叉叠化（第 101 到 108 行）：对类型为 luma 的转场（只有 93.8 秒一处），找到在该时刻结束的 V1 片段（A24_AI-9），调用 AddTransition({'type': 'Cross Dissolve', 'category': 'simple', 'position': 'end', 'alignment': 'center', 'duration': max(2, fr(dur))})。脚本请求 35 帧，Resolve 在时间线上实际放下的是 15 帧（2337 到 2351 帧，即 93.48 到 94.08 秒），与两侧各 15 帧的手柄一致。
9. V2、V3 特殊转场（第 109 到 119 行）：每个转场文件只放一次，startFrame = 0，长度 n = fr(start + dur) − fr(start)，recordFrame = T0 + fr(start)。轨道由 free_track() 分配：先看 V2 在这段时间是否空闲，空闲就放 V2，否则放 V3。成片里只有 T11_ink（56.4 秒起）与 T10_light（到 56.5 秒）重叠 2 帧，被放到 V3，其余都在 V2。转场文件是完整的不透明画面，盖住接缝两侧的 V1。
10. three.js 落叶叠加层（第 120 到 123 行）：FX_T1b_leaves.mov（1920x1080，ProRes 4444 带直通 alpha，44 帧，两阵槭叶和翅果从镜头前刮过）放在第 987 帧起 44 帧（39.48 到 41.24 秒，树苗长大的 T1b 镜头里），轨道同样由 free_track() 分配，成片里落在 V2。这个文件的制作见[第 4 章](04_代码镜头竹林与three.js.md)。
11. V4 文字层（第 125、126 行）：overlay_text.mov 整条放在 V4，从 T0 开始，2750 帧。
12. V5 宣纸纹理（第 127 到 131 行）：paper_4k.png 放在 V5，从 T0 开始，请求长度 fr(END) = 2750 帧；SetProperty('CompositeMode', resolve.COMPOSITE_MULTIPLY)（正片叠底），SetProperty('Opacity', 35.0)。
13. 声音（第 133 到 136 行）：DX.wav、MX.wav、FX.wav、AMB.wav 依次放在 A1 到 A4，从 T0 开始，整条（mediaType = 2，只放声音）。
14. 结果（第 137 行）：result = {'timeline': 时间线名, 'v1_items': V1 片段数, 'log': 每一步是否成功}。调用方检查 log 中所有条目都以 True 结尾。成片装配的结果是 v1_items = 27，失败条目为空。

从导出的 .drt 时间线文件读出的结构（帧号从成片开头算）：

| 轨道 | 内容 |
|---|---|
| V1 画面 | 27 个片段，0 到 2750 帧首尾相接；93.8 秒一处 15 帧 Cross Dissolve |

V5 只有 125 帧：Resolve 导入静帧时的默认长度是 5 秒，AppendToTimeline 请求的 2750 帧被截到素材长度。所以成片里宣纸纹理层只覆盖 0 到 5.0 秒；因为纹理很淡（见 8.2.9），5 秒处没有可见的跳变，跳变扫描在这里也没有标记。

### 8.3.4 叠加顺序

Resolve 从上往下合成，高轨道盖在低轨道上：

1. V1：代码镜头、AI 镜头和 93.8 秒的交叉叠化；
2. V2、V3：预渲染转场，完整不透明画面，转场时段内完全替换 V1；V3 在上，所以 56.4 到 56.48 秒两帧显示 T11；
3. V2 上的落叶叠加层按直通 alpha 盖在画面上；
4. V4：文字层按 alpha 盖在上面；
5. V5：宣纸纹理以正片叠底、35% 不透明度乘在最上面（0 到 5 秒）。

时间线是 3840x2160，渲染时缩成 1920x1080（见 8.4），所以 AI 镜头在成片里相当于从 1280x720 放大 1.5 倍；代码镜头先放大到 4K 再缩回 1080p，转场、文字层和落叶层按 1080p 素材适配到 4K 时间线后再缩回，最终都接近原样。

### 8.7.1 跳变扫描：scan_jumps.py

目的：找出突然的画面变化（硬切、闪白、跳帧）和颜色跳变。

算法（work/v16k/scan_jumps.py）：

1. 用 OpenCV 逐帧读成片，每帧缩到 480x270（面积平均），转成 0 到 1 的浮点；
2. 画面差 d[i]：本帧与上一帧逐像素、逐通道绝对差的平均值；
3. 局部水平 med[i]：d 在前后各 12 帧（共 25 帧）窗口里的中位数；
4. 颜色跳变 dc[i]：本帧与上一帧的整帧平均颜色（B、G、R 三个均值）之差，取三个通道里最大的那个；
5. 标记条件：(d > 0.06 且 d > 3.5 × med + 0.01) 或 dc > 0.045。第一个条件找"远高于附近运动水平的突变"，第二个条件找整体颜色的突然变化。

命令：

```bash
.venv_ai/bin/python work/v16k/scan_jumps.py renders/v18/R13_v5_1_1080p.mp4
```

### 8.7.3 逐帧比对：PSNR

用途有两个：证明工程包上重建的时间线与主时间线渲染完全一致（见 8.6）；证明两个渲染之间的差别只出现在应该出现的时段（例如两个渲染只有文字层不同时，差别只能出现在字幕的显示时段）。

用 ffmpeg 的 psnr 滤镜逐帧比对两个渲染，把每帧结果写进文件：

```bash
ffmpeg -nostats -i renders/v18/R13_v5_1_1080p.mp4 -i renders/v18/R13_v5_1080p.mp4 -lavfi "[0:v][1:v]psnr=stats_file=work/v19/_v51_psnr.txt" -f null -
```

统计文件每行一帧：n（帧号，从 1 开始）、mse_avg、mse_y、mse_u、mse_v、psnr_avg、psnr_y、psnr_u、psnr_v。两帧完全相同时 PSNR 为 inf。统计不相同的帧数（第 6 列是 psnr_avg）：

```bash
awk '{split($6,a,":"); if (a[2] != "inf") n++} END {print n, "frames differ"}' work/v19/_v51_psnr.txt
```

再把不相同的帧号连成连续时段（时间 = (n − 1) / 25），和改动内容出现的时段对照。

判定标准：

- 打包验证：只看 ffmpeg 输出的平均值，要求 average:inf，即所有帧逐像素一致；
- 局部改动验证：不相同的帧必须集中在改动内容的显示时段内；时段之外如有零星差异，PSNR 应在 38 dB 以上，并抽查确认没有像素差超过 8 个色阶（编码器码率分配带来的微小差别，不是内容变化）。

work/v19/_v51_psnr.txt 是成片渲染 R13_v5_1_1080p.mp4 与 R13_v5_1080p.mp4 的比对，两者只有文字层里 6 条字幕不同：2750 帧里 538 帧不同，其中主体是 6 段，7.04 到 10.96、12.20 到 15.96、17.36 到 19.96、20.84 到 23.76、24.52 到 27.96、30.36 到 32.96 秒，正好是这 6 条字幕的显示时段，最低 PSNR 38.3 到 42.6 dB；另有 36.84 到 36.92、46.92 到 48.28、100.60 到 105.12 秒的零星帧，PSNR 38.6 到 55.6 dB，抽查 47.2 秒没有任何像素差超过 8 个色阶。

## 8.8 复现时要注意的细节

- 93.8 秒的交叉叠化：plan.json 写的是 1.4 秒，脚本请求 35 帧，Resolve 实际放下 15 帧（0.6 秒，93.48 到 94.08 秒），与 0.6 秒的手柄长度相同。
- 宣纸纹理层只覆盖 0 到 5 秒（静帧默认长度 5 秒，见 8.3.3）。
- 取整：fr() 用 Python 的 round()，0.5 时取偶数。转场窗口起点大多不在整帧上（例如 23.3 秒 = 582.5 帧），转场文件按窗口起点的精确时刻逐帧渲染，放到时间线时起点取整，最多相差半帧。个别转场在时间线上的长度与文件差一帧：T04_reprint 和 T17_lumakey 文件 35 帧、时间线 36 帧；X0314_reprint 文件 35 帧、时间线只用前 34 帧。这些边缘帧两侧画面相同，跳变扫描没有标记。
- 落叶叠加层的位置写死在 build_resolve.py 里（第 987 帧起 44 帧，盖在 37.8 到 42.6 秒 T1b 镜头的两次季节变色上），不从 plan.json 读取。
- renders/v18/elements 里还有两个 plan.json 不引用的文件（S26_Title18.mov、T17_mist.mov），成片没有用到；装配只放 plan.json 列出的文件。

- export18.py 开头说明里的用法行写的是 export16.py，实际命令是 export18.py。
