### 数据结构

film() 返回六个值：`(t0, t1, shots, labels, texts, trans)`。

1. `t0 = 0.0`，`t1 = END = 110.0`：全片起止（秒）。
2. `shots`：镜头列表，每项是 `(a, b, frame_fn)`。a、b 是这个镜头在成片里的起止秒数；`frame_fn(t)` 输入成片时间 t（秒），返回一帧 1920x1080、float32、RGB、取值 0 到 1 的画面。关键约定：**frame_fn 在 [a, b] 之外也必须能出画**（手柄，handle：镜头起止点之外的画面），转场和叠化要用到镜头两端之外的画面（见 5.5 节）。
3. `labels`：成片里为空列表（没有任何标签纸签和印章）。
4. `texts`：文字对象列表，每个对象有 `draw(img, t)`，把自己在时刻 t 的样子画到 img 上（见 5.9 节）。
5. `trans`：转场表。镜头表里先写成 `trans_at = {接点秒数: (类型, 时长[, 参数字典])}`，再换算成 `{结束于该接点的镜头序号 j: 规格}`（edit18.py 第 1032 到 1053 行）。
6. 转场函数注册在 `C.TRANS` 字典里，统一接口 `f(A, B, u, **参数)`：A 是前一个镜头在当前时刻的画面，B 是后一个镜头在同一时刻的画面，u 从 0 走到 1。

长镜头用 `Chain18` 表示（edit18.py 第 291 到 303 行）。它由几段 AI 视频首尾相接组成，每段写成 `(名称, 起, 止, 首帧关键帧, 尾帧关键帧, 源区间[, 变速参数])`，段与段之间如果不是同一帧，就在 `xfades` 里写转场。成片里有两个长镜头：

- chain1（16.6 到 24.0 秒）：S1、S2、S3、S4 四段，天目林学院石门到浙江林学院校门。四段首尾帧相同（每段的首帧就是上一段的尾帧，生成时就用它做首帧），段间直切。
- chain2（27.4 到 37.8 秒）：E2、S7 两段，2000 年的东湖原址到 2004 年的图书馆，31.4 秒一处"重印"转场。

### 一帧画面是怎么算出来的

渲染循环在 edit16.py 的 render()（第 216 到 238 行），edit18 把自己的 film() 交给它：

1. 第 f 帧对应 `t = f / 25`。
2. 找到 `a <= t` 的最后一个镜头 i。
3. 逐个检查转场：若 t 落在某个接点 bt 的窗口 `[bt - d/2, bt + d/2)` 里，就取 `A = S[j](t)`、`B = S[j+1](t)`、`u = (t - (bt - d/2)) / d`，输出 `TRANS[类型](A, B, u, **参数)`。窗口以接点为中心，前后各占一半。
4. 否则输出 `S[i](t)`。
5. 依次画上 labels（空）和 texts。
6. 转成 16 位 RGB 交给 ffmpeg，编码为 ProRes 422 HQ（ProRes 是剪辑常用的高画质中间编码格式）。

## 5.2 第一步：测量每段素材的运动量

**输入**：libtv_jobs/out/ 下全部 AI 视频；竹林渲染 ~/Movies/ZAFU/renders/v18_bamboo.mov。

**脚本**：work/v18/motion_profiles.py（AI 视频）；竹子由 edit18.py 的 Bamboo._motion() 用同样方法测量（第 697 到 706 行），测完追加进同一个文件。

**做法**：

1. 逐帧解码，缩到 480x270，转灰度。
2. 相邻两帧之间算 DIS 光流（光流：逐像素估计两帧之间的运动；DIS 是 OpenCV 里的快速光流算法 `DISOpticalFlow`，这里用 ULTRAFAST 预设）。
3. 取光流幅值的第 90 百分位数，作为这一帧的运动量 m（单位：480 像素宽画面上，每个源帧移动多少像素）。用第 90 百分位而不是平均值，是因为版画画面大片是平涂的纸色和天空，平均值会被这些不动的区域拉低。

**输出**：work/v18/motion.json，格式 `{片名: {"fps": 源帧率, "m": [每帧运动量]}}`，第 0 帧记 0。

```bash
.venv_ai/bin/python work/v18/motion_profiles.py
```

## 5.3 第二步：按运动量变速

### 规则

运动大的地方放慢，空镜和静止的纸面快过，速度曲线平滑，镜头之间速度衔接。做法是：**每个源帧在成片里占用的时间，与它的运动量的 p 次方成正比**。运动量大的帧占的时间多，播放就慢；运动量小的帧占的时间少，播放就快。p=1 时，每个成片帧里画面移动的距离基本相等；p=0 时退化成匀速线性取帧。

### 算法（edit18.py 第 105 到 123 行，motion_map）

输入：运动量序列 m、源帧率 fps、源区间 [s0, s1]、镜头时长 dur，以及参数 p、floor、smax、smin、sigma、start_slow、end_slow。

1. 取源区间内的帧：`i0 = round(s0·fps)`，`i1 = round(s1·fps)`，`mm = m[i0+1 : i1+1]`（进入每一帧的运动量）。
2. 权重 `w = max(mm, floor) ^ p`。floor 是下限，防止完全静止的帧权重为 0（那样会被无限加速）。
3. 用高斯核平滑权重，`sigma = 0.35` 秒（核半宽 3·sigma），两端按边缘值延伸。这样速度曲线是连续的，不会一帧快一帧慢。
4. 可选的首尾放慢：`w ×= 1 + start_slow·exp(-x/0.6) + end_slow·exp(-(x_end - x)/0.6)`，x 是距离片段开头的源秒数。
5. 限速：迭代 30 次，每次先算 `c = dur·fps / Σw`（每单位权重对应多少成片秒），再把 w 夹在 `[1/(c·smax), 1/(c·smin)]` 之间。效果是每一帧的播放倍速都在 smin 和 smax 之间。
6. 每个源帧占用的成片时间 `dt = c·w / fps`，累加得到成片时间轴 F，对应的源时间轴 `S = s0 + 序号/fps`，最后把 F 缩放到正好等于 dur，S 的末项设为 s1。
7. 播放时 `源时间 = interp(t - a, F, S)`。

### 跨切点的速度衔接

- **小星球接 AI-1（5.6 秒，直切）**：小星球的平面版画就是 AI-1 解码出来的第 0 帧（libtv_jobs/out/AI-1_f0.png），所以切点两侧是同一张画。小星球的推进用对数缩放的三次 Hermite 曲线（edit18.py 第 376 到 379 行）：在 0、3.3、5.6 秒取值 ln(0.76·s_p)、ln(s_p)、0，斜率 0.05、0.14、0.30（每秒对数缩放量），所以 5.6 秒时推进速度是 0.30，即每帧约 1.2%，交给 AI-1 时 AI-1 正以约 1.6 倍速推进。2.6 秒以后，小星球每帧在 t-0.005、t、t+0.005 秒取三个子帧平均，带上和 AI 视频相当的运动模糊；4.9 到 5.6 秒逐渐提高细节（高斯 σ1.2 的反锐化，增益从 1 升到 1.24），让切点两侧清晰度一致。
- **O1 接 AI-G（12.9 秒，直切）**：O1 是作为 AI-1 和 AI-G 之间的桥生成的，尾帧就是 AI-G 的首帧。O1 末端按运动量放到约 5 到 6 倍，AI-G 的手工曲线开头约 5.9 倍，两侧速度接近。
- **长镜头 S1 接 S2（18.8 秒）**：S2 整段裁切放大 6%（`zoom = 1.06`），S1 在 18.1 到 18.8 秒把裁切从 1.00 平滑升到 1.06（`zoom_ramp`），这一步藏在穿松林的运动里完成，切点两侧画面比例一致。
- **镜头两端之外**：每个变速镜头记下两端的速度（`v0`、`v1`，取首尾 0.3 秒或镜头长度的三分之一里的平均斜率），镜头之外的手柄按这个速度继续走（见 5.5 节）。

**检查**：用 5.10 节的 join_sheet.py 排出切点前后 ±0.6 秒的画面，并逐帧测量切点两侧每帧的推进比例、横移和清晰度（拉普拉斯方差）是否连续。工程文档记录的 5.6 秒切点实测值：推进每帧 1.37%、1.28%（切点）、1.37%，横移接近零。

## 5.4 第三步：AI 镜头去顿挫

### 问题

Seedance 生成的视频按 4 帧一组出帧：一组之内镜头不是匀速前进的，每 4 步里有一步偏短、下一步偏长；T1b（树苗长大）更是每 4 帧重复一帧；4 帧里还有一帧比其他帧更锐。直接播放会形成每秒约 6 次的细微顿挫。所以先测出每帧真实的位移，再按真实时间重排帧。

### 测量：cadence.py

**输入**：libtv_jobs/out/ 下全部 AI 视频，包括成片用到的 16 段（AI-1、O1、AI-G、S1、S2、S3、S4、E2、S7、T1b、AI-4、AI-5、AI-7、AI-8、AI-9、AI-10）。

**脚本**：work/v18/cadence.py。

**做法**：

1. 逐帧解码，缩到 640 像素宽（INTER_AREA），转灰度。
2. `steps[i]`：第 i-1 帧到第 i 帧的 DIS 光流（MEDIUM 预设）幅值的平均值，只统计有纹理的像素（前一帧拉普拉斯平方大于 20 的像素；有纹理的像素少于 500 个时才用全图平均）。平涂的纸面和天空不提供运动信息，所以排除。
3. `sharp[i]`：第 i 帧的拉普拉斯方差（锐度）。
4. `sigma[i]`：如果某帧锐度超过前后各 4 帧中位数的 1.10 倍，用二分法（14 次，σ 在 0 到 2.5 之间，640 像素尺度）求出能把它模糊到中位锐度的高斯 σ，再换算到源像素。
5. 打印每段视频按"帧号除以 4 的余数"分组的平均步长比（步长除以 9 帧滑动平均），用来确认 4 帧节奏。

**输出**：work/v18/cadence.json，格式 `{片名: {"steps": [...], "sharp": [...], "sigma": [...]}}`。

```bash
.venv_ai/bin/python work/v18/cadence.py
```

按 cadence.json 复算的 4 帧节奏（只统计 9 帧平均步长大于 0.6 像素、确实在动的帧；余数 0 到 3 分别对应帧号除以 4 的余数）：

| 片段 | 帧数 | 平均步长（像素） | 余数 0 | 余数 1 | 余数 2 | 余数 3 |
|---|---|---|---|---|---|---|
| AI-1 | 193 | 2.42 | 0.89 | 1.10 | 1.03 | 0.96 |
| O1 | 193 | 6.94 | 0.97 | 1.01 | 1.00 | 0.99 |
| S1 | 145 | 4.60 | 1.09 | 0.99 | 0.96 | 0.96 |
| S3 | 145 | 2.67 | 1.04 | 0.99 | 0.96 | 0.95 |
| S4 | 121 | 2.55 | 0.97 | 1.10 | 0.95 | 0.91 |
| E2 | 169 | 0.71 | 1.05 | 1.02 | 0.98 | 0.93 |
| T1b | 241 | 1.29 | 1.73 | 1.02 | 0.07 | 1.01 |
| AI-7 | 193 | 1.66 | 1.06 | 0.97 | 0.96 | 0.96 |
| AI-10 | 193 | 7.96 | 1.10 | 0.96 | 0.97 | 0.94 |

T1b 余数 2 的步长只有平均值的 7%（重复帧），紧接着余数 0 的一步是 1.73 倍。AI-G、S2、S7、AI-4、AI-5、AI-8、AI-9 测得的步长很小，没有达到统计门槛。

### 把每帧放回真实时间（true_index）

edit18.py 第 129 到 139 行。对一段 n 帧的视频：

1. `st = steps[1:n]`，`ms` = st 的 9 帧滑动平均（两端按边缘值延伸）。
2. 置信度 `w = clip(ms / 0.15, 0, 1)`：平均位移小于 0.15 像素的地方几乎不动，测出的比值没有意义，w 趋于 0，这些帧保持原来的时间（静止的片段保持原样）。
3. 比值 `r = clip(st / ms, 0.1, 2.5)`：这一步相对附近平均步长偏短还是偏长。
4. 每帧的时间增量 `step = 1 + w·(r - 1)`，累加得到 tau，再整体缩放使 `tau[n-1] = n - 1`（总时长不变）。
5. 结果 `tau[i]` 就是第 i 帧的"真实时间"（以帧为单位）：短的一步时间增量小，重复帧几乎不占时间。

取帧时反过来查：要源时间 x 秒的画面，就求 `kk = interp(x·fps, tau, [0, 1, ..., n-1])`，得到一个带小数的帧号，再在 kk 的整数部分和下一帧之间生成中间帧。复算的修正量：每帧时间的局部修正平均 0.03 到 0.34 帧（T1b 最大），单帧最大约 1.2 帧。

只有 cadence.json 里该片段的帧数与视频帧数完全一致时才启用重排，否则按原始帧号取帧（edit18.py 第 254 到 255 行）。

### 光流中间帧（_between）

edit18.py 第 211 到 244 行。要第 i0 帧和第 i0+1 帧之间、位置 f（0 到 1）的画面：

1. 在素材原尺寸（1280x720）上算两帧之间的 DIS 光流（MEDIUM 预设），缓存最近 10 对。
2. 把第 i0 帧沿光流前推 f，把第 i0+1 帧沿光流回拉 1-f（`cv2.remap`，双线性，边缘复制）。
3. 失败判定：如果两张变形后的图平均差超过"两张原图平均差的 1.6 倍加 4.0"，说明光流解释不了这个变化（淡入淡出、片内硬切），退回普通的线性混合。
4. 否则只输出离得近的那一张变形图（f < 0.5 用前一帧变形，否则用后一帧变形），不取两者平均。两张变形图在对不齐的地方平均会糊掉细刻线。

这是真正的中间帧：画面里的物体被移到中间位置，而不是两个位置的叠影。

### 快放时的半帧快门

edit18.py 第 245 到 265 行。先估当前播放速度 `v = |源时间(t+0.02) - 源时间(t-0.02)| / 0.04`（源秒每成片秒），半个成片帧对应的源时长 `span = v·0.5/25`，换算成源帧数 `n_s = span·fps`。

- `n_s <= 1.2`（24 fps 素材约 2.5 倍速以下）：只取一张中间帧，再做清晰度稳定。
- `n_s > 1.2`：在 `[源时间 - span/2, 源时间 + span/2]` 里均匀取 `m = min(5, ceil(n_s) + 1)` 张中间帧求平均，相当于 180 度快门的运动模糊。这样快放的镜头是连续流动的，而不是一跳一跳。这些帧的模糊是有意的，不再锐化。

成片里用到快门的镜头：S1（最高约 8.8 倍）、S2（6 倍）、S3（最高 6 倍）、O1 结尾（约 5.6 倍）、AI-G 开头（约 5.9 倍）、AI-1 中段（约 3 倍）。

### 清晰度稳定（_steady）

edit18.py 第 266 到 277 行。AI 视频本来就有一帧更锐的节奏，中间帧又比整帧略软，播放时会"一清一糊"。处理：

1. 预先算每个源帧的拉普拉斯方差，再取前后各 6 帧（13 帧窗口）的中位数作为目标锐度。
2. 对输出帧算拉普拉斯方差 v，增益 `g = clip(sqrt(目标 / v), 0.72, 1.65)`。
3. `|g - 1| < 0.04` 时不处理；否则用高斯 σ1.2 分出底层，细节层乘以 g：`输出 = 底层 + (原图 - 底层)·g`。g 大于 1 时补细节，小于 1 时压细节。

cadence.json 里的 sigma 在成片里没有使用（edit18.py 第 256 行把它全部置 0），锐度统一由 _steady 处理。

### 首尾帧处理（_edges）

生成视频的第 0 帧（或最后一帧）常常就是参考关键帧本身，和下一帧之间有一个跳。判定方法（edit18.py 第 167 到 176 行）：在 160x90 灰度图上，如果第 0、1 帧的平均差大于"第 1、2 帧平均差的 2 倍加 1.0"，就跳过第 0 帧；末端同理。之后的取帧和手柄都以跳过后的首末帧为界。

### 导出 AI 镜头时的颜色稳定

这几步在 export18.py 导出 AI 镜头时执行（第 83 到 111 行）：

- **季节和生长镜头的颜色闪烁**（T1b、S7、AI-9、E2、AI-10）：每帧缩到 64x36 求 RGB 均值，用 0.8 秒（19 帧）滑动平均得到平滑曲线，每帧乘以增益 `平滑值 / 原值`，增益夹在 0.8 到 1.25。
- **T1b 的季节跳变**：源时间落在 2.7 到 3.4、3.9 到 4.9、5.15 到 6.6 秒时，用前后各 0.3 秒（约 7 帧）的原始帧平均替代，做成短暂的时间混合。
- **AI-10 的一段灰云**：源时间 2.6 到 4.6 秒，亮度乘以 `1 + 0.22·sin(π(st - 2.6)/2)`，与前后云海一致。

**AI 镜头的导出规格**：每帧调用 `pic(t)`（中间帧、快门、清晰度稳定、手柄），再按需要居中裁切放大后缩回原尺寸，保持 1280x720 原生分辨率，25 fps，ProRes 422 HQ（yuv422p10le），前后各带 0.6 秒手柄。放大到成片分辨率在达芬奇里用 Super Scale（达芬奇自带的超分辨率放大）完成（[第 8 章](08_达芬奇装配输出与检查.md)）。

```bash

```

## 5.5 第四步：手柄延续，转场里两边都在动

**规则**：转场和叠化的窗口里，前一个镜头已经过了它的结束点，后一个镜头还没到它的开始点。这两段多出来的画面叫手柄。手柄里的画面必须继续运动，不能定格，否则每次转场都会"顿一下"。

### AI 镜头的手柄（AIShotMap）

edit18.py 第 142 到 206 行。

1. **源时间继续走**：`src_time(t)` 在镜头开始之前按开头速度 v0 往回推，在结束之后按结尾速度 v1 往前推（第 161 到 166 行）。
2. **素材用完时按运镜继续推**：如果推算出的源时间超出了素材首末帧（跳过参考帧之后的首末帧），就取首帧或末帧，按"首末 5 帧的运镜"继续变形（`raw_at` 和 `_edge_motion`，第 177 到 206 行）：
   - 在首（末）帧上找最多 400 个角点（`goodFeaturesToTrack`，质量 0.01，最小间距 12 像素）；
   - 用金字塔 LK 光流跟踪到第 5 帧；
   - 用 RANSAC（随机抽样一致：反复抽点拟合，剔除跟踪错的点；重投影阈值 2.0 像素）拟合相似变换（缩放、旋转、平移，`estimateAffinePartial2D`），换算成每秒的对数缩放、角度、以画面中心为基准的 dx、dy；
   - 手柄里第 τ 秒的画面 = 首（末）帧按 `缩放 exp(log缩放·τ)`、`角度·τ`、`平移·τ` 变形（`warpAffine`，边缘镜像）。
3. 导出时 AI 元素文件覆盖 `[a - 0.6, b + 0.6]`（export18.py 第 17、79 行，HANDLE = 0.6 秒），转场文件也直接用这些画面渲染。

### 代码镜头的手柄

- **静帧推移镜头（Parallax18）**：运动参数 `u = t_local / dur` 不做缓入缓出，并允许在 -0.4 到 1.4 之间延伸（edit18.py 第 351 行），所以镜头在进入转场时已经在动，转场结束后还在动。每个静帧镜头的推移覆盖哪段时间，见 5.6 节表格。
- **一草一木**：底层第一张卡片就是 AI-4 的画面，继续运动。
- **竹子**：结束之后按结尾速度继续走，最多走到素材倒数第二帧（edit18.py 第 712 到 715 行）；开始之前停在源 0.45 秒那一帧，这段时间处在 42.6 秒林间光转场最亮的部分。
- **研究图版**：用缓入缓出的推镜（scenes.py 的 Parallax，4% 推近，2.6 秒），66.8 秒之前处在起始位置，这段时间重印转场正在把它的墨稿印到纸上。

chain1 的 S1 到 S4 段间直切，切点两侧本来就是同一帧；chain2 在 31.4 秒用重印转场，E2 和 S7 都用上面的手柄机制在窗口里继续运动。

## 5.6 静帧版画镜头

### 规则

静帧版画镜头在剪辑里遵守一条时间规则：推移从头到尾匀速，而且推移覆盖的时间比镜头本身长，两侧转场的窗口和手柄里画面都在动。画面上的飘雾、光束、浮尘、落叶和推移用同一个时钟，全程跟着走；要跟着画面走的文字（校训金字）在配音念到的时刻刻出。匀速超采样推移（Parallax18）、浮尘与落叶（Motes）、光束（rays）、薄雾带（MistBand）和校训金字的做法与全部参数见[第 4 章](04_代码镜头竹林与three.js.md)第三节和第四节，本节只讲它们在时间线上怎样对时。

### 匀速超采样推移（Parallax18）

推移进度 `u = clip(t_local / dur, -0.4, 1.4)`（edit18.py 第 351 行），匀速，不做缓入缓出。t_local 是镜头自己的时钟：u = 0 是推移起点，u = 1 是推移终点；超出 0 到 1 的部分按同一速度外推，前后最多各再走 40%。所以只要推移的时间覆盖住镜头和两侧转场的窗口，切点两边就不会有停顿。

## 5.8 转场

### 通用机制

1. **位置和窗口**：每处转场写在 trans_at（或长镜头的 xfades）里，窗口以接点为中心，`[接点 - 时长/2, 接点 + 时长/2)`。
2. **两侧画面**：窗口里每一帧都用两个镜头在同一时刻 t 的画面计算（手柄机制保证两边都在动）。
3. **预渲染**：除普通叠化外，所有转场由 export18.py 渲染成完整画面的 ProRes 422 HQ 文件 trans/T##_<类型>.mov（##是结束于该接点的镜头在 film() 里的序号），长镜头内部的转场渲染成 trans/X0314_reprint.mov。在达芬奇里它们放在 V2、V3 轨，正好盖住 V1 上两个镜头的切点。
4. **普通叠化**：类型 'luma' 不预渲染，plan.json 记为 luma，装配时在 V1 上加达芬奇的 Cross Dissolve（居中，1.4 秒）。
5. 窗口内 `u = (t - 窗口起点) / 时长`，从 0 到 1。下文的 smoothstep 指 `x²(3 - 2x)`。

```bash
.venv_ai/bin/python work/v16k/export18.py trans
```

### 1. 水墨晕开（T_ink）

**函数**：work/v14/comp.py 第 547 到 556 行。**含义**：新画面像墨或水落在宣纸上一样从一点晕开，边缘略深。

1. 噪声场 `_N`（comp.py 第 496 到 499 行）：种子 21，135x240 的随机数高斯模糊 σ6 放大到全画面，加 0.35 倍的 270x480 随机数 σ3，归一化到 0 到 1。
2. 距离场 `Rc`：每个像素到晕开中心 `(cx·W, cy·H)` 的距离，横向除以 W/2、纵向除以 H/2，再除以 1.42。
3. 晕开场 `v = 0.40·blur(_N, σ9)/最大值 + 0.60·Rc`：以距离为主，噪声让边缘不规则。
4. 阈值 `th = 1.25u - 0.05`；遮罩 m 在 `v < th - 0.08` 处为 1（全是 B），在 `v > th` 处为 0，中间 0.08 宽 smoothstep 过渡。
5. 湿边 `edge = smoothstep(0, 0.25, m)·smoothstep(0.6, 0.25, m)`，只在过渡带里非零。
6. 输出 `(A·(1 - m) + B·m)·(1 - 0.10·edge)`：过渡带压暗 10%。

参数：`fringe = 0.10`；晕开中心 cx、cy 默认 (0.5, 0.5)，按画面内容选在"墨的来处"（见总表）。

### 2. 粒子汇聚（particles3d.render）

**函数**：work/v16k/particles3d.py 第 139 到 213 行，导出时调用（export18.py 第 131 到 139 行）。**含义**：旧画面碎成细小的颜料颗粒，按深度飞起，镜头继续向前；底下的纸面褪成白纸；颗粒汇聚到几个点后消失，留一点暖光；新画面从这些点像墨一样晕开。

**深度**：用 Depth Anything V2 Large（Hugging Face `depth-anything/Depth-Anything-V2-Large-hf`，Transformers 加载，在 Apple GPU 的 MPS 上运行）估计画面 A 的深度：输入缩到 1036x588，输出放大回 1920x1080，归一化到 0 到 1，高斯 σ2（particles3d.py 第 13 到 22 行）。

**步骤**：

1. **颗粒**：每 2x2 像素一颗（位置加 0 或 1 像素随机抖动），共 960x540 = 518400 颗，每颗带 A 在该点的颜色。随机种子 58。
2. **放进三维**：垂直视场 40 度，焦距 `f = 0.5H / tan(20°)`；深度 d 换算成距离 `Z = 1 / (1/80 + (1/6 - 1/80)·d)`（近处 6，远处 80）；按针孔模型反投影出每颗的三维坐标。
3. **汇聚点**：在 B 上找 4 个结构最强的点（particles3d.py 第 25 到 34 行，centres）：灰度 Sobel 梯度幅值高斯 σ40，乘以偏向画面中心的高斯（0.55W、0.55H），依次取最大值，每取一个就清掉半径 260 像素内的值。每颗颗粒分配给离它最近的汇聚点。
4. **时间安排**（M 是转场进度 0 到 1）：
   - 起飞 `rel = 0.03 + 0.20·(1 - 深度) + 0.08·随机`：近处的颗粒先飞；
   - 到达 `arr = 0.34 + 0.14·随机`：全部在 0.34 到 0.48 之间到达；
   - 只有 55% 的颗粒参与飞行（`keep`），云团更轻。
5. **运动**：镜头前移 `move[0]`、上下移动 `move[1]`，按 `smoothstep(M/0.6)` 进行，每颗颗粒按新的相机位置重新投影；每颗从它的投影位置沿 `smoothstep(τ)^1.25` 飞向汇聚点（τ 是这颗颗粒从起飞到到达的进度），加 22 像素幅度的旋绕（`sin(πτ)` 包络）；颗粒起飞 0.06 进度内淡入，飞完最后 18% 淡出；离镜头太近（距离小于 1.2）的颗粒淡出。
6. **绘制**：每颗颗粒按双线性权重分到 4 个像素上（不是平均色块，颗粒是分开的点）；每帧取 3 个子帧（`K = 3`），形成短的运动拖尾。
7. **底下的纸**：`left = clip((M - 0.02 - 0.24·(1 - 深度)) / 0.24)`，近处先褪；纸面 = 画面 A 的当前帧·(1 - left) + 纸色 (0.935, 0.905, 0.835)·left；颗粒以 0.9 的不透明度叠在上面。
8. **汇聚处的暖光**：每个汇聚点一个高斯光斑（σ26 像素），在 M = 0.26 到 0.60 之间出现，强度 0.28，颜色 (1.0, 0.93, 0.75)。
9. **墨晕**：`ub = clip((M - 0.37) / 0.63)`，用 Bleed 遮罩（particles3d.py 第 37 到 56 行）把 B 的当前帧显出来：
   - 到最近汇聚点的距离 d；
   - 边缘噪声 = 软团块（H/12 x W/12 随机场，σ3，乘 46 像素）+ 宣纸纤维（全尺寸随机场，横向 σ4、纵向 σ0.9，乘 7 像素），种子 3；
   - 半径 `R = 40 + (d 最大值 + 200)·ub^1.4`，`x = (R - (d + 噪声)) / 34`，透明度 = `clip(0.5 + x)` 再高斯 σ2；
   - 湿边 `exp(-((x - 0.4)/1.1)²)·(1 - ub³)`，B 在湿边处压暗 16%。
10. **两侧继续运动**：export18 把窗口里两个镜头每一帧的画面作为 A_seq、B_seq 传入，纸面用 A 的当前帧，墨晕显出 B 的当前帧。
11. 第一帧严格等于 A，最后一帧严格等于 B，两端与镜头无缝。

### 3. 重印（T_reprint）

**函数**：edit18.py 第 495 到 517 行。**含义**：旧画面像印在纸上的画被洗掉一样褪成纸（亮部先褪，不均匀），新画面先印出墨稿（暗部），再从中间晕入颜色。

1. 预备（种子 9）：细噪声 N（H/24 x W/24 随机场三次插值放大，高斯 σ6，归一化）；大团块噪声 NL（6x9 随机场放大，高斯 σ40，归一化）；距离场 R（到 (W/2, 0.55H) 的距离，归一化后除以 1.42）；纸 = scenes.py 的 paper()。
2. **洗掉旧画**（u 从 0 到 0.52）：`f = ramp(u, 0, 0.52)·1.7 - 0.35`；遮罩 `ma = smoothstep(clip((f - (0.8·NL + 0.2·(1 - A的亮度))) / 0.55 + 0.5))`；`纸面 = A·(1 - ma) + 纸·ma`。A 的亮处阈值低，先被洗掉；NL 让洗掉的范围成片、不均匀。
3. **印墨稿**（u 从 0.2 到 0.62）：`p = smoothstep(ramp(u, 0.2, 0.62))`，墨量 `ink = clip(1.1 - 1.25·B的亮度)`（只有 B 的暗部有墨）；`印后 = 纸面·(1 - 0.85·p·ink·(0.85 + 0.15·N))`。
4. **晕入颜色**（u 从 0.42 到 1）：`c = ramp(u, 0.42, 1)`；`m = smoothstep(clip((1.35c - 0.18 - (0.5N + 0.5R)) / 0.2 + 0.5))`，从中心向外、带噪声地扩开；`输出 = 印后·(1 - m) + B·m`。

### 4. 云雾（T_mist）

**函数**：edit18.py 第 469 到 491 行。**含义**：镜头穿过一层雾，雾从下方漫起把画面笼住，前一个画面在雾中换成后一个，雾再向上散去。雾最浓时底下的画面仍然隐约可见。

1. 预备（种子 5）：在 1/4 尺寸、(1920+800)x(1080+400) 的画布上生成两层分形噪声。
   - 远层 L1 = 0.62·(σ26) + 0.30·(σ12) + 0.16·(σ5)；
   - 近层 L2 = 0.55·(σ16) + 0.35·(σ7)；
   - 各自归一化后三次插值放大。在 1/4 尺寸上模糊，没有网格感。
2. 漂移：远层取样窗口偏移 `(400 + 90(u - 0.5), 200 - 50(u - 0.5))`，近层的偏移是远层的 2.6 倍和 2.2 倍（视差）；`n1 = 0.65·远层 + 0.35·近层`。
3. 浓度：`dens = sin(πu)^0.75·(1 + 0.35·(y - 0.5)·(1 - 2u))`，y 是 0（顶）到 1（底）的高度。进入时底部先浓，离开时顶部最后散。
4. 雾量 `fog = clip(1.05·dens + 0.18·tanh(n1) - 0.12, 0, 0.80)`，上限 0.80。
5. 切换：`sw = smoothstep(clip((u - 0.5)·4 - 0.25·tanh(n1) + 0.5))`，A 在 u=0.5 附近带噪声边缘地换成 B，藏在最浓的雾里。
6. 雾色 `(0.945, 0.925, 0.875)·(0.985 + 0.03·tanh(n1))`；`输出 = 底图·(1 - fog) + 雾色·fog`。

### 5. 林间光（T_light）

**函数**：edit18.py 第 520 到 528 行。**含义**：光线变亮到画面浸在暖光里，下一个画面从光中出现。普通叠化的重影藏在亮光里。

1. 光强 `g = sin(πu)^1.4·peak`。
2. 换画只发生在最亮的一段：`m = smoothstep(ramp(u, 0.34, 0.66))`，`底图 = A·(1 - m) + B·m`。
3. 亮部先亮：`k = g·(0.55 + 0.45·底图亮度)`。
4. `输出 = 底图 + (1 - 底图)·k·warm`。

默认 `warm = (1.0, 0.90, 0.66)`（暖金），`peak = 0.74`。

### 6. 雪光（T_light 的冷色版本）

同一个函数，参数 `warm = (0.92, 0.95, 1.0)`（冷白），`peak = 0.6`，用在雪中的花卡片接天目山云海（55.95 秒）：雪先发光，云海从光里出来。

### 7. 亮部先行（T_lumakey）

**函数**：edit18.py 第 532 到 548 行。**含义**：新画面先在它自己的亮处出现（雪、云、雾、天空、白墙），而且优先在旧画面也是亮的地方，然后是中间调，暗部最后；边缘宽而软，下面垫一点普通淡化，不会画出硬轮廓线。

1. 噪声（种子 4）：H/16 x W/16 随机场三次插值放大，高斯 σ20，归一化。
2. 键值 `key = 0.55·B亮度 + 0.25·A亮度 + 0.20·噪声`，高斯 σ8，再按第 2 和第 98 百分位拉伸到 0 到 1。
3. 阈值 `th = 1.25 - 1.5u`；`m = smoothstep(clip((key - th) / 0.35 + 0.5))`。
4. 垫底淡化 `w = smoothstep(u)`；最终遮罩 `0.7·m + 0.3·w`；`输出 = A·(1 - 遮罩) + B·遮罩`。

### 8. 卡片滑入（Plants18）

**函数**：edit18.py 第 558 到 590 行。**含义**：一草一木做成拼贴：俯瞰校园的 AI-4 画面缩小成第一张卡片落在纸上，仍在运动；四张植物版画像不透明的剪纸卡片依次滑入，每张落在一拍上。任何一帧都不会出现两张画透叠。

1. 节拍：`beat(k) = 48.3 + k·(59.6 - 48.3)/16`，每拍 0.70625 秒，与配乐的小节网格对齐。
2. 第一张卡片：从 `t0 = beat(6) = 52.5375` 秒起 0.6 秒，`u0 = smoothstep(ramp(t, t0, t0 + 0.6))`，AI-4 画面缩到 `(1 - 0.11·u0)`，转 -1.0 度；之后每落一张新卡片，再缩 4%、再转 -0.6 度。
3. 四张版画（codex/out/K_plant_lotus.png、K_plant_ginkgo.png、K_plant_redleaf_snow.png、K_plant_blossom_snow.png）分别落在 beat(7) 到 beat(10)：53.244、53.950、54.656、55.363 秒。
4. 每张提前 0.6 秒开始从画外整张滑入，方向依次为右、左、下、右，起点在 1.02 倍画宽（或 1.05 倍画高）之外，`v = smoothstep(ramp(t, 落点 - 0.6, 落点))`；大小 0.93 倍；旋转 `±(3.0·(1 - v) + 1.0·后续卡片数)` 度，左右交替。
5. 每张卡片（`_card`）：仿射变换后用 -1 作为画外标记得到遮罩；纸边 = 13x13 膨胀减原遮罩，填宣纸纹理；投影 = (遮罩 + 纸边) 高斯 σ16 后向下 12、向右 9 像素，压暗 30%；卡片本身完全不透明。

## 5.9 屏幕文字

### 字体和字形

全片文字用思源宋体的可变字重版本 data/fonts/NotoSerifSC[wght].ttf，用 Pillow 栅格化（comp.py 第 25 到 30 行设置字重轴）。每个字单独画成一张 RGBA 小图，画布宽 1.2 倍字号、高 1.35 倍字号（comp.py 第 164 到 168 行）。年份、日期等整行文字用 glyph_row() 一次画成一行。

### 字幕的样式（InkCaption）

edit17.py 第 131 到 147 行，edit18.py 第 926 到 933 行。

| 项目 | 值 |
|---|---|
| 字号、字重 | 40 像素，字重 500 |
| 字色 | 墨色 RGB (40, 33, 26) |
| 位置 | 水平居中，字形框顶边在 y = 1080 - 118 = 962 |
| 字距 | 每字前进 40 像素；逗号、顿号换成 22 像素空格 |
| 纸色微光 | 每个字的透明度先 7x7 膨胀，再高斯 σ12（0.3 倍字号），乘 1.6 后截到最高 0.62，四周留 28 像素边；颜色是纸色 (0.95, 0.925, 0.86)，先画在字下面 |
| 浮现 | 每个字 0.42 秒，out-cubic 缓出；从下方 22 像素（0.55 倍字号）处升起，升起过程中字形底部被一条看不见的基线遮住，像从纸缝里浮上来；透明度同步从 0 到 1 |
| 淡出 | 0.25 秒 smoothstep，整行一起淡出 |

纸色微光的作用：墨色字在深色画面上也能读，同时不用黑色投影，保持版画的纸墨质感。

### 字幕对时：按停顿切短语（align_chunks.py）

字幕以短语为单位出现，每个短语的开口时间由 work/v18/align_chunks.py 从配音分轨的能量曲线里测出（按停顿切短语，而不是逐字对时），写成 work/v18/chunks.json，格式 `{句号: [[短语, 起, 止, [每字时间]], ...]}`。edit18.py 读入 chunks.json 后，把每句的逐字时间表换成短语内均匀分布的时间（第 61 到 68 行）。测量方法的每一步和参数见[第 1 章](01_文案配音与时间表.md) 1.6.2 节。

### 一次一行：字幕的出现和消失（subtitles18）

edit18.py 第 936 到 956 行按 chunks.json 排出全片字幕，规则是：每个短语在开口前 0.08 秒整体浮现，短语里的字每隔 0.03 秒依次升起；一行字幕在说完 0.5 秒后淡出，下一行来得早时提前到下一行出现前 0.3 秒淡出，但每行至少完整显示 0.6 秒，所以屏幕上同一时刻只有一行字幕。字幕里的"它"统一写作"他"（第 58 行）。完整规则和全片 23 条字幕的时间表见[第 1 章](01_文案配音与时间表.md) 1.6.3 和 1.6.4 节。

开场问句、"在这里，我们博览古今，我们学参天地"和结尾"浙江农林大学 生日快乐"不出底部字幕，分别由竖排字和片尾贺卡承担。

## 5.10 导出与检查

### 导出全部素材

work/v16k/export18.py 读入 edit18.film()，把全片拆成 renders/v18/elements/ 下的一组素材：shots/ 里的代码镜头和 ai/ 里重排时间后的 AI 镜头（ProRes 422 HQ，前后各带 0.6 秒手柄，长镜头拆成独立片段，共 27 个，编号 0 到 26），trans/ 里的预渲染转场，全长的透明字幕层 overlay_text.mov，以及记录每个素材成片起止、文件内起点、源区间和转场位置的时间线计划 plan.json。build_resolve.py 再按 plan.json 在达芬奇里装配（V1 画面，V2、V3 转场，V4 字幕，V5 宣纸纹理）。各子命令、`only=编号` 的用法、编码规格和 plan.json 的字段见[第 8 章](08_达芬奇装配输出与检查.md) 8.2 和 8.3 节。

### 跳变扫描（scan_jumps.py）

work/v16k/scan_jumps.py：逐帧缩到 480x270，算与前一帧的平均绝对差 d 和平均颜色的变化 dc；d 的局部水平取前后各 12 帧（25 帧窗口）的中位数。满足"d > 0.06 且 d > 3.5 倍局部水平 + 0.01"或"dc > 0.045"的帧列为跳变，打印时间。对成片跑一遍，所有标记都应该是已知的转场渐变或直切。下面命令里的 renders/v18/R13_v5_1_1080p.mp4 是达芬奇渲染出的 1080p 成片（见[第 8 章](08_达芬奇装配输出与检查.md)）。

```bash
.venv_ai/bin/python work/v16k/scan_jumps.py renders/v18/R13_v5_1_1080p.mp4
```

### 接缝联络表（join_sheet.py）

work/v18/join_sheet.py：每个接点一行，取接点前后 -0.6、-0.36、-0.12、0、+0.12、+0.36、+0.6 秒共 7 帧，每帧缩成 320x180，行首写上接点时刻，拼成一张 JPEG。

```bash
.venv_ai/bin/python work/v18/join_sheet.py renders/v18/R13_v5_1_1080p.mp4 joins.jpg 5.6,9.9,12.9,16.6,18.8,19.8,22.2,24,27.4,31.4,37.8,42.6,48.3,52.54,55.95,56.85,59.6,62.6,66.8,69.4,73,80,87.8,90.8,93.8,101.2
```

看图时检查三件事：转场两侧的画面是否都在动；切点前后的推进方向和速度是否一致；有没有一帧突然变色、变亮或变糊。
